# Руководство администратора

## Требования

| Компонент | Версия / объём |
|---|---|
| ОС | Linux (Ubuntu, Astra, РЕД ОС); для разработки подходит macOS |
| Python | 3.11 или новее |
| Tesseract OCR | 4 или новее (нужны LSTM-модели). Модели `rus` и `eng` берутся из `tessdata/` проекта, если они там есть, иначе из установленных языковых пакетов |
| CPU | от 2 ядер; договор на 33 страницы обрабатывается около 3,5 минут (все страницы проходят полный OCR) |
| RAM | от 2 ГБ плюс место под `/run`: договор на 33 страницы на проверке занимает около 35 МБ, акт — около 1 МБ |
| Сеть | Доступа в интернет не нужно. Внутренняя LLM необязательна |

## Установка через Docker (рекомендуется)

```bash
git clone https://github.com/s-verbin/pdf-redactor.git /opt/pdf-redactor
cd /opt/pdf-redactor

# каталог задач в tmpfs: переживает перезапуск контейнера, не попадает на диск,
# пересоздаётся после перезагрузки сервера (uid 10001 — пользователь внутри образа)
echo "d /run/redactor 0700 10001 10001 -" > /etc/tmpfiles.d/pdf-redactor.conf
systemd-tmpfiles --create /etc/tmpfiles.d/pdf-redactor.conf

STATE_DIR_HOST=/run/redactor docker compose up -d --build
```

Сервис слушает `127.0.0.1:8088`, наружу его публикует reverse proxy (пример nginx ниже,
`client_max_body_size` должен быть больше `MAX_UPLOAD_MB`). Ограничения CPU и памяти контейнера
заданы в `docker-compose.yml`. Обновление: `git pull && STATE_DIR_HOST=/run/redactor docker compose up -d --build`.

## Установка в закрытом контуре (без Docker)

### 1. Собрать архив (на машине с интернетом)

Нужна та же ОС, архитектура и версия Python, что на сервере: wheel-пакеты зависят от платформы.

```bash
deploy/make_offline_bundle.sh
```

Получится `dist/redactor.tar.gz`: код, модели OCR, документация и wheel-пакеты.

### 2. Поставить Tesseract на сервер

Из локального зеркала репозиториев ОС:

```bash
apt install tesseract-ocr        # Ubuntu / Astra
dnf install tesseract            # РЕД ОС
tesseract --version              # должно быть 4.x или 5.x
```

### 3. Развернуть сервис

```bash
useradd --system --home /opt/redactor --shell /usr/sbin/nologin redactor
tar -xzf redactor.tar.gz -C /opt          # создаст /opt/redactor
cd /opt/redactor
python3 -m venv .venv
.venv/bin/pip install --no-index --find-links wheels -r requirements.txt
cp .env.example .env && vi .env
chown -R redactor: /opt/redactor
```

### 4. Запустить как службу

```bash
cp deploy/redactor.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now redactor
systemctl status redactor
```

Сервис слушает порт 8088. Проверка: откройте `http://<сервер>:8088/`.

## Настройки (`.env`)

| Параметр | По умолчанию | Назначение |
|---|---|---|
| `WORKERS` | `1` | Сколько документов обрабатывается одновременно. Остальные ждут в очереди. При `WORKERS>1` Tesseract автоматически ограничивается одним потоком (`OMP_THREAD_LIMIT=1`) |
| `MAX_UPLOAD_MB` | `60` | Максимальный размер загружаемого файла |
| `RESULT_TTL_MIN` | `30` | Через сколько минут без активности удалять документ, который прошёл обработку или завершился ошибкой |
| `STATE_DIR` | `./data` | Каталог хранения задач. В systemd-юните задан `/run/redactor` |
| `MAX_ATTEMPTS` | `3` | Сколько раз пробовать документ, если обработка прерывалась (перезапуск, сбой) |
| `OCR_DPI` | `300` | Разрешение для распознавания |
| `OUTPUT_DPI` | `200` | Разрешение страниц в итоговом PDF |
| `JPEG_QUALITY` | `80` | Качество страниц в итоговом PDF (влияет на размер файла) |
| `OCR_LANG` | `rus+eng` | Языки Tesseract |
| `LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY`, `LLM_TIMEOUT` | пусто | Внутренняя LLM с OpenAI-совместимым API. Необязательна: без неё работают правила |

После изменения `.env` перезапустите службу: `systemctl restart redactor`. Задачи при этом не
теряются (см. ниже).

## Хранение данных и перезапуск

Каждая задача хранится в отдельном каталоге `STATE_DIR/<id>/`:

| Файл | Когда существует |
|---|---|
| `job.json` | Всё время жизни задачи: статус, отчёт, предложенные плашки |
| `source.pdf` | Пока задача в очереди или обрабатывается. Удаляется сразу после анализа |
| `page_N.jpg`, `prev_N.jpg` | Пока документ на проверке: все страницы без закраски (JPEG высокого качества) и уменьшенные превью |

По умолчанию в systemd-юните `STATE_DIR=/run/redactor`. Это tmpfs, то есть оперативная память:
- **Перезапуск службы** (`systemctl restart`, падение процесса) задачи не теряет. Благодаря
  `RuntimeDirectoryPreserve=yes` каталог остаётся. После старта сервис возвращает в очередь
  прерванные задачи в исходном порядке, а документы на проверке остаются доступны.
- **Перезагрузка сервера** очищает `/run`, незавершённые задачи пропадут. Чтобы переживать
  и её, укажите дисковый каталог (например, `STATE_DIR=/var/lib/redactor`). Учтите, что тогда
  документы будут временно лежать на диске.

Если процесс падает на одном и том же файле `MAX_ATTEMPTS` раз, задача помечается ошибкой, чтобы
не блокировать очередь.

Очищать хранилище вручную не нужно: задачи удаляются по кнопке «Удалить» или через
`RESULT_TTL_MIN`. Чтобы экстренно удалить всё: `systemctl stop redactor && rm -rf /run/redactor/*`.

## Важно: только один процесс

Очередь живёт внутри процесса. **Не запускайте uvicorn с `--workers N` и не поднимайте несколько
копий на одном `STATE_DIR`**: они начнут обрабатывать одни и те же задачи. Параллельность
задаётся только через `WORKERS`.

## Безопасность

- **Встроенной авторизации нет.** Ограничьте доступ на уровне сети (firewall, VLAN) или поставьте
  перед сервисом reverse proxy с аутентификацией (например, nginx с Kerberos/LDAP).
- Id задачи (случайный 128-битный) работает как пароль к документу: списка чужих задач API
  не отдаёт.
- Найденные фрагменты текста (паспорт, адрес) API не отдаёт, только категории. В журнал службы
  они тоже не пишутся.
- Каталог `STATE_DIR` создаётся с правами `0700`.
- Для HTTPS используйте reverse proxy. Сам сервис работает по HTTP.

Пример nginx:

```nginx
server {
    listen 443 ssl;
    server_name redactor.corp.local;
    client_max_body_size 64m;
    location / {
        proxy_pass http://127.0.0.1:8088;
        proxy_read_timeout 120s;
    }
}
```

В этом случае поменяйте в юните `--host 0.0.0.0` на `--host 127.0.0.1`.

## Журнал и диагностика

```bash
journalctl -u redactor -f
```

Что пишется в журнал:
- `восстановлено задач: N, возвращено в очередь: M` — старт после перезапуска;
- `job <id> проанализирован за N c, страницы: [1, 2, …]` — документ готов к проверке;
- `job <id>: собран PDF, страниц 2 из 33, плашек: 21` — пользователь скачал результат;
- `job <id> прерван (попытка 1 из 3)` со стеком — сбой обработки, задача будет повторена.

Частые проблемы:

| Симптом | Причина и решение |
|---|---|
| `TesseractNotFoundError` | Tesseract не установлен или его нет в `PATH` службы |
| `Failed loading language 'rus'` | Нет `tessdata/rus.traineddata` в каталоге сервиса и не установлен пакет `tesseract-ocr-rus`. Диагностика: `.venv/bin/python -m app.check` |
| Документы долго стоят в очереди | Мало CPU. Увеличьте `WORKERS` (не больше числа ядер). Один договор — около 3,5 минут на воркер |
| «LLM недоступна» в интерфейсе | Проверьте `LLM_BASE_URL`. Сервис работает и без LLM |
| После перезагрузки сервера задачи пропали | Так и задумано для `/run`. См. «Хранение данных» |

## Обновление

```bash
systemctl stop redactor
# распаковать новую версию поверх /opt/redactor, сохранив .env
.venv/bin/pip install --no-index --find-links wheels -r requirements.txt
systemctl start redactor
```

Задачи в `/run/redactor` переживают обновление. Если между версиями изменился формат задач,
несовместимые задачи будут удалены при старте, и пользователям придётся загрузить файлы заново.
