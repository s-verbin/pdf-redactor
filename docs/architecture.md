# Устройство сервиса (для разработчиков)

## Общая схема

```
Браузер                           Сервер (один процесс uvicorn)
───────                           ─────────────────────────────
загрузка PDF ── POST /api/jobs ─► store: source.pdf + job.json ─► очередь (asyncio.Queue)
                                                                        │
опрос статуса ◄─ GET /api/jobs/{id} ◄─ job.json            воркер (WORKERS шт.)
                                                                        │
                                              pipeline.analyze():       ▼
                                                OCR всех страниц → detect → предложенные плашки
                                                store: page_N.jpg, prev_N.jpg, job.json; source.pdf удаляется
                                                                        │
редактор плашек ◄─ GET /pages/{n}.jpg ◄─────────────────────────────────┘
      │
«Собрать PDF» ── POST /build {плашки} ─► pipeline.build_pdf(): закраска в пикселях → PDF из JPEG
```

## Модули

| Файл | Что делает |
|---|---|
| `app/config.py` | Настройки из окружения и `.env`, путь к `tessdata` |
| `app/ocr.py` | Рендер страниц (PyMuPDF), оценка и исправление наклона, стирание линий таблиц, OCR через Tesseract с координатами слов |
| `app/grid.py` | Поиск линий таблиц на скане: ячейка вокруг прямоугольника, ячейка значения справа от подписи строки |
| `app/detect.py` | Поиск конфиденциальных фрагментов: правила, таблицы, LLM; преобразование в прямоугольники |
| `app/llm.py` | Промпт и вызов внутренней LLM (OpenAI-совместимый API) |
| `app/pipeline.py` | `analyze()` — OCR всех страниц, предложение плашек и подсказка, какие страницы оставить; `build_pdf()` — сборка итогового файла из выбранных страниц; `process()` — оба шага без проверки (для CLI) |
| `app/store.py` | Хранение задач в `STATE_DIR` |
| `app/main.py` | FastAPI: API, очередь, воркеры, восстановление после перезапуска, очистка по TTL |
| `app/static/index.html` | Фронт: загрузка, очередь, редактор плашек (без сборки и зависимостей) |
| `app/cli.py` | Обработка из консоли в автоматическом режиме |
| `app/check.py` | Проверка окружения: Python, пакеты, Tesseract, языковые модели, каталог задач, LLM |

## Анализ документа (`pipeline.analyze`)

1. **Тип документа.** Распознаётся первая страница. Если в начале есть «Акт приёма-передачи»,
   это `act`, иначе `contract`. OCR часто пишет «АКТ» латиницей, поэтому похожие латинские
   буквы нормализуются в кириллицу.
2. **Обрабатываются все страницы** (шаги 3–5 для каждой). Какие из них войдут в PDF, решает
   пользователь. Для подсказки (`report.suggested`) используется уже распознанный текст:
   - `act` — все страницы;
   - `contract` (`suggest_contract_pages`) — стр. 1 и первая страница после неё, где есть «Подписи
     Сторон», «Арендодатель» и «Арендатор». Поиск останавливается на первом приложении (шапка
     «Приложение № N к Договору»). Если заголовок не найден, берётся страница перед первым
     приложением; если и это не удалось — только стр. 1 и предупреждение.
3. **OCR страницы** (`ocr.ocr_page`):
   - наклон ищется перебором углов ±3° с шагом 0,1° по резкости горизонтальной проекции;
   - изображение поворачивается, с копии для OCR стираются длинные горизонтальные и вертикальные
     линии: с ними Tesseract путает строки в таблицах;
   - Tesseract (`--psm 3`, `rus+eng`) возвращает слова с координатами.
4. **Поиск данных** (`detect.detect`), см. ниже.
5. **Результат:** страница итогового разрешения (`OUTPUT_DPI`), повёрнутая на тот же угол
   (JPEG q=92: PNG на 30+ страниц занял бы ~100 МБ), превью шириной 1200 px и плашки в долях
   от размера страницы (0..1), чтобы не зависеть от разрешения.

## Поиск конфиденциальных данных (`detect.py`)

### Блок арендодателя

`owner_scope()` ищет блок реквизитов арендодателя. Он начинается с заголовка «АРЕНДОДАТЕЛЬ»,
оформленного как заголовок (заглавными, в кавычках или с двоеточием; в тексте условий слово
пишется обычно). Если OCR исказил заголовок, начало ищется по «Индивидуальный предприниматель».
Блок заканчивается на блоке арендатора: «Арендатор», «Акционерное», «Общество»,
«Местонахождение» или «ОГРН», потому что заголовок «АРЕНДАТОР» OCR иногда теряет.

Блок засчитывается, только если внутри есть якорь: «паспорт», «рождения», «зарегистрирован»,
«регистрации», «корреспонденции», «проживания». Без этого подписи в приложениях
(«АРЕНДОДАТЕЛЬ: Индивидуальный предприниматель ___ /И. И. Иванов») принимались бы за блок
реквизитов, и белый список закрасил бы их.

- **Блок найден** (стр. 1 договора, реквизиты, акт): персональные данные ищутся только в нём,
  белый список применяется.
- **Блока нет** (условия договора, приложения): персональные данные ищутся по всей странице,
  белый список не применяется. Лишние срабатывания уберёт пользователь.

Слова на левом поле (x < 7% ширины, рукописные пометки) не учитываются. Деньги ищутся по всей
странице всегда.

### Правила

| Правило | Где | Что закрывает |
|---|---|---|
| Белый список (`_owner_paragraph_hit`) | Абзац об арендодателе-ИП (стр. 1 договора, акт) | Всё, кроме заголовка, «Индивидуальный предприниматель ФИО», ОГРНИП/ИНН с номером, «с одной стороны, и» |
| `MONEY_RES` | Вся страница | Число + «руб/₽/р.», сумма прописью в скобках с «рубл» |
| `PASSPORT_RE` | Блок арендодателя | От «паспорт» до кода подразделения или следующего реквизита |
| `BIRTH_RES` | Блок арендодателя | «5 марта 1980 года рождения», «05.03.1980 г.р.», «место рождения …» |
| `ADDRESS_RE` | Блок арендодателя | Значение после «зарегистрирован по адресу», «адрес регистрации / для корреспонденции / проживания» |
| `PHONE_RE`, `EMAIL_RE` | Блок арендодателя | Телефоны РФ, e-mail |
| `TABLE_LABELS` | Таблица реквизитов | Ячейка значения справа от подписи строки («…паспорта», «…рождения», «Адрес регистрации», «…корреспонденции», «Телефон», «e-mail/почта») |

Белый список — главное правило для абзацев. Он работает «от обратного» и потому устойчив
к ошибкам OCR: на фото с изогнутыми строками «место рождения г. Самара» может распознаться как
«о 2019Г- мара», и регулярки такой текст не найдут, а белый список всё равно его закроет.
Для таблицы реквизитов белый список не применяется (признак таблицы — слова «ФИО», «Расчётный
счёт», «БИК»): там банковские реквизиты нужно оставить.

### LLM (необязательно)

Если заданы `LLM_BASE_URL` и `LLM_MODEL`, OCR-текст страницы по строкам уходит в модель. Она
возвращает JSON с категориями и дословными фрагментами. `locate()` нечётко ищет каждый фрагмент
среди слов страницы: сравнивает окна слов через `difflib`, порог 0,75. Личные данные ищутся
только в блоке арендодателя, иначе похожий адрес объекта «перетягивает» совпадение. При
ошибке LLM анализ продолжается на правилах, а пользователь видит предупреждение.

### От слов к прямоугольникам

- `words_to_rects()` строит прямоугольник по непрерывной серии выбранных слов в строке. Серия
  разрывается на невыбранном слове (чтобы не закрыть ФИО между двумя фрагментами) и на
  перепаде высоты (строки на фото изогнуты).
- `finalize_rects()` добавляет отступ. Если прямоугольник лежит в узкой ячейке таблицы
  (не шире 70% страницы и не выше 15%), закрывается вся ячейка вместе со словами, которые
  выступают за её линии. Слова из колонки подписей таблицы (левая узкая колонка) не закрываются.

## Сборка PDF (`pipeline.build_pdf`)

Плашки рисуются прямо в пикселях копии страницы (Pillow), страница сжимается в JPEG
(`JPEG_QUALITY`) и вставляется в новый PDF единственной картинкой на странице исходного размера.
Метаданные и XMP очищаются, объекты пересобираются (`garbage=4`). В файле нет текста, шрифтов,
аннотаций и исходных изображений.

## Очередь и хранилище

- В памяти процесса только лёгкое состояние задач (`Job`). Файлы лежат в `STATE_DIR/<id>/`
  (см. `store.py`), `job.json` пишется атомарно (tmp + `os.replace`).
- При загрузке сначала пишется `source.pdf`, потом `job.json`. Каталог без `job.json` при
  старте считается мусором и удаляется.
- Воркер увеличивает `attempts` и сохраняет его до начала работы. Непредвиденная ошибка
  (в том числе убитый при остановке службы Tesseract) возвращает задачу в очередь. После
  `MAX_ATTEMPTS` попыток задача становится ошибкой. `ProcessingError` («не PDF», «нет страниц»)
  окончательна сразу.
- `restore()` при старте поднимает все задачи. `queued` и `processing` возвращаются в очередь
  по времени создания.
- `janitor()` раз в минуту удаляет задачи в статусах `review`/`error`, не тронутые
  `RESULT_TTL_MIN` минут. Любой запрос к задаче продлевает срок.
- Фронт хранит в `localStorage` только id задач и координаты плашек. После перезапуска сервера
  или обновления страницы список и правки восстанавливаются.

Статусы задачи: `queued → processing → review` или `→ error`; `processing → queued` при прерывании.

## API

| Метод | Путь | Описание |
|---|---|---|
| `POST` | `/api/jobs` | multipart: `file` (PDF), `kind` = `auto` \| `contract` \| `act`. Возвращает задачу |
| `GET` | `/api/jobs/{id}` | Статус, `position` в очереди, `stage`, `report` (страницы, `suggested` — предложенные к отправке, категории, предупреждения), `pages` (`src_page`, `aspect`, `boxes`) |
| `GET` | `/api/jobs/{id}/pages/{n}.jpg` | Превью страницы без закраски (только в статусе `review`) |
| `POST` | `/api/jobs/{id}/build` | JSON `{"pages": [{"keep": true, "boxes": [{"x0","y0","x1","y1"}, …]}, …]}` — по элементу на каждую страницу, координаты 0..1. В PDF попадают страницы с `keep: true`. Возвращает PDF |
| `DELETE` | `/api/jobs/{id}` | Удалить задачу (кроме находящихся в очереди или обработке) |

Коды ошибок: `400` — не PDF, неизвестный тип, не совпадает число страниц, не выбрано ни одной страницы; `404` — задачи нет;
`409` — документ ещё не готов; `410` — страницы удалены; `413` — файл слишком большой;
`422` — координаты вне 0..1.

## Разработка

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/uvicorn app.main:app --port 8088 --reload
```

Проверка на файле без веб-интерфейса. В `debug/` появятся PNG закрашенных страниц, а в консоли
отчёт с найденными фрагментами:

```bash
.venv/bin/python -m app.cli договор.pdf --debug debug
.venv/bin/python -m app.cli договор.pdf --keep suggested   # только стр. 1 и с подписями
.venv/bin/python -m app.cli договор.pdf --keep 1,15
.venv/bin/python -m app.cli акт.pdf --kind act --no-llm
```

### Как добавить правило

1. Регулярка для текста — в `detect.py` рядом с `MONEY_RES` / `PASSPORT_RE`; вызов — в
   `_rule_hits()` через `add(stream, match, category)`. `owner.text` — текст блока
   арендодателя, `full.text` — всей страницы.
2. Новая категория — в `CATEGORY_NAMES` (подпись для пользователя) и в промпте `llm.py`.
3. Проверьте на реальных сканах через CLI с `--debug`: OCR ошибается иначе, чем кажется
   по чистому тексту.

### Известные ограничения

- Правила настроены на типовой договор аренды нежилого помещения, где арендодатель —
  индивидуальный предприниматель, а арендатор — компания. Для
  арендодателя-юрлица белый список не срабатывает, работают только регулярки.
- На страницах-копиях документов (справки, свидетельства) мелкий текст распознаётся плохо,
  персональные данные там могут остаться незакрытыми. Такие страницы лучше исключать.
- Проверено на двух документах. Перед вводом в эксплуатацию прогоните 10–20 реальных сканов.
- Авторизации нет (см. руководство администратора).
